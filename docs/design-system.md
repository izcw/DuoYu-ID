# 多鱼账号 UI 规范

本规范是后续新增或修改样式的默认依据。风格参考 LumeHub，品牌属于多鱼账号；用户明确提出的新要求优先。

## 风格与取舍

参考 LumeHub 的登录组件：白色画布、黑色主按钮、浅灰细边框、低饱和度辅助文字、宽松间距、小圆角。登录表单和二维码是同一主区域的不同状态。参考分析及源码链接见 [lumehub-reference.md](lumehub-reference.md)。

登录页以内容与操作为中心，不添加营销标语、没有功能的链接、假二维码、虚构备案或协议。多鱼账号保留当前独立登录页，后台继续使用 Art Design Pro 基础布局，不必把所有页面改为固定尺寸弹窗。

## 视觉参数

| 项目 | 默认值 |
| --- | --- |
| 页面背景 | 登录页 #FFFFFF；后台可用 #FAFAFA |
| 主要文字 | #111111，正文 14–16px |
| 次要文字 | #727782；弱提示 #939AA5，12–13px |
| 主操作 | #000000 背景、白色文字；悬停 #262626 |
| 边框 | #D9DCE2，1px；分隔线 #EEEEEE |
| 圆角 | 按钮与输入框 5px；弹窗与面板 8px |
| 登录表单 | 最大宽度 420px；移动端左右留白 24–28px |
| 输入框 | 高 42px；左右内边距 14px；输入项间距 18px |
| 表单按钮 | 登录、验证码发送、通行密钥、iPhone 扫码按钮高 42px；主按钮宽度铺满表单 |

黑白灰是界面主色；红色用于错误，绿色用于明确成功，橙色用于必要注意事项，不用于大面积装饰。品牌 Logo 本身的颜色保留，不能据此把界面改回绿色主题。

## 品牌资产

- `admin/public/logo.png`：用户提供的原始图片，按原比例展示，用 `object-fit: contain`，不裁切主体、不拉伸、不自行重绘，保留原始透明度。
- `admin/public/favicon.ico`：浏览器页签图标。登录页、扫码确认页和后台均引用 `/favicon.ico`。
- 登录方式图标使用用户提供的 `admin/public/passkey.png` 与 `admin/public/iphone.png`，24px 等比显示，装饰图片使用空 alt，按钮保留可访问名称。
- 用户头像与项目 Logo 分开；用户头像缺省使用中性人像占位图。
- 对外名称为“多鱼账号”，英文“Duoyu ID”。不复制 LumeHub/ThinKing 的 Logo、名称、备案号或协议内容。

## 组件与行为

- 输入框必须保留可访问的 label，视觉上可仅显示 placeholder；密码右侧使用眼睛按钮，并提供 aria-label 与状态。
- 表单提供加载、错误、禁用状态；键盘可操作，焦点可见。不能只依赖颜色表达状态。
- 登录页操作结果使用 Element Plus Message 顶部消息提示，成功/错误区分类型，支持关闭和自动消失；切换登录方式清除旧消息，不再使用表单下方的 #message 提示块。组件随项目本地构建，不依赖外部 CDN。
- 默认无多余提示；需要验证码、失败或权限说明时才展示。验证码校验通过后自动创建不存在的账号，无“注册”勾选框。
- 主按钮使用简洁“登录”。密码模式只有邮箱与密码；找回密码继续验证邮箱。
- 手机扫码状态包括生成中、待扫码、待确认、已拒绝、过期、失败。失效二维码提供刷新，切换回邮箱时取消本次二维码会话。
- 弹窗只在有明确上下文和关闭行为时添加关闭按钮，不在独立登录页放无意义的关闭图标。
- 管理端新建、编辑、准入配置、账号安全表单必须使用独立路由页面，不使用编辑弹窗。页面包含返回入口、清晰分区、保存/取消、加载及错误状态；涉及未保存内容时提供离开确认。弹窗仅用于危险操作或离开页面的确认。
- 邮件使用表格布局、黑灰配色及小圆角；关键信息不依赖外部图片加载。

## 修改后的检查

检查桌面与 390px 手机视口；确认没有横向溢出、标题截断、键盘焦点丢失或未完成的加载遮罩。预览登录页、密码模式、二维码和受影响的后台页面。维护同一套颜色与组件尺寸，避免在单个页面引入新的视觉体系。
