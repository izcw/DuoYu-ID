# 多鱼账号 UI 规范

本规范是后续新增或修改样式的默认依据。风格参考 LumeHub，品牌属于多鱼账号；用户明确提出的新要求优先。

## 风格与取舍

参考 LumeHub 的登录组件：白色画布、黑色主按钮、浅灰细边框、低饱和度辅助文字、宽松间距、小圆角。登录表单和二维码是同一主区域的不同状态。参考分析及源码链接见 [lumehub-reference.md](lumehub-reference.md)。

登录页以内容与操作为中心，不添加营销标语、没有功能的链接、假二维码、虚构备案或协议。多鱼账号保留当前独立登录页，后台继续使用 Art Design Pro 基础布局，不必把所有页面改为固定尺寸弹窗。

## 视觉参数

| 项目 | 默认值 |

| 页面背景 | 登录页 #FFFFFF；后台可用 #FAFAFA |
| 主要文字 | #111111，正文 14–16px |
| 次要文字 | #727782；弱提示 #939AA5，12–13px |
| 主操作 | #000000 背景、白色文字；悬停 #262626 |
| 边框 | #D9DCE2，1px；分隔线 #EEEEEE |
| 圆角 | 按钮与输入框 5px；弹窗与面板 8px |
| 登录表单 | 最大宽度 420px；移动端左右留白 24–28px |
| 输入框 | 高 42px；左右内边距 14px；输入项间距 18px |
| 表单按钮 | 登录、验证码发送、通行密钥、iPhone 扫码按钮高 42px；主按钮宽度铺满表单 |

黑白灰是界面主色；红色用于错误，绿色用于明确成功，橙色用于必要注意事项，不用于大面积装饰。品牌 Logo 本身的颜色保留，不能据此把界面改回绿色主题。

## 品牌资产

- `admin/public/logo.png`：用户提供的原始图片，按原比例展示，用 `object-fit: contain`，不裁切主体、不拉伸、不自行重绘，保留原始透明度。
- `admin/public/favicon.ico`：浏览器页签图标。登录页、扫码确认页和后台均引用 `/favicon.ico`。
- 登录方式图标使用用户提供的 `admin/public/passkey.png` 、`admin/public/iphone.png` 与 `admin/public/authenticator.png`，24px 等比显示，装饰图片使用空 alt，按钮保留可访问名称。
- 用户头像与项目 Logo 分开；用户头像缺省使用中性人像占位图。
- 对外名称为“多鱼账号”，英文“DuoYu ID”。不复制 LumeHub/ThinKing 的 Logo、名称、备案号或协议内容。

## 组件与行为

- 输入框必须保留可访问的 label，视觉上可仅显示 placeholder；密码右侧使用眼睛按钮，并提供 aria-label 与状态。
- 表单提供加载、错误、禁用状态；键盘可操作。输入框聚焦时保留默认浅色细边框，不增加描边、外框、加深边框或光晕；按钮、链接等保留键盘焦点提示。不能只依赖颜色表达错误状态。
- 登录页操作结果使用 Element Plus Message 顶部消息提示，成功/错误区分类型，支持关闭和自动消失；切换登录方式清除旧消息，不再使用表单下方的 #message 提示块。组件随项目本地构建，不依赖外部 CDN。
- 默认无多余提示；需要验证码、失败或权限说明时才展示。验证码校验通过后自动创建不存在的账号，无“注册”勾选框。
- 验证码模式主按钮为“登录/注册”，密码模式主按钮为“登录”。密码模式只有邮箱与密码；找回密码继续验证邮箱。
- 手机扫码状态包括生成中、待扫码、待确认、已拒绝、过期、失败。失效二维码提供刷新，切换回邮箱时取消本次二维码会话。
- 弹窗只在有明确上下文和关闭行为时添加关闭按钮，不在独立登录页放无意义的关闭图标。
- 管理端新建、编辑、准入配置、账号安全表单必须使用独立路由页面，不使用编辑弹窗。页面包含返回入口、清晰分区、保存/取消、加载及错误状态；涉及未保存内容时提供离开确认。弹窗仅用于危险操作或离开页面的确认。
- 邮件使用表格布局、黑灰配色及小圆角；关键信息不依赖外部图片加载。

## 修改后的检查

检查桌面与 390px 手机视口；确认没有横向溢出、标题截断、键盘焦点丢失或未完成的加载遮罩。预览登录页、密码模式、二维码和受影响的后台页面。维护同一套颜色与组件尺寸，避免在单个页面引入新的视觉体系。

## 管理页面统一结构（2026-10-27）

- 一级页标题下使用细分隔线；面板标题与正文分层；辅助文字默认 #727782，避免过浅灰导致阅读困难。
- 概览快捷入口必须可实际导航；资料摘要等只读卡片不得显示可点击光标。
- 运行状态位于“安全与设置”，只展示真实读取的计数和配置，不把零积压等同于公网健康或邮件送达。
- 列表筛选、分页和可重试错误保持一致；手机上表格在容器内横向滚动，页面本身不得横向溢出。
- 独立编辑页的保存区域保持可达；不使用新增/修改弹窗。
- 页面自检使用 admin/tests/ui-refresh.mjs，覆盖 1440px 与 390px；登录控件高度维持 42px。

## 样式资源与移动导航

- 登录与扫码基础变量位于 admin/public/auth/base.css，各页面样式分别在 login.css 和 scan.css；Go 模板仅引用本地资源。
- 当前正式支持浅色风格，隐藏未验收的主题/布局设置；恢复这些入口前需补齐完整主题验收。
- 菜单图标通过 admin/scripts/build-icons.mjs 从源码引用生成本地图标集，新增图标后运行构建，不回退外部 CDN。
- 手机首次加载和路由切换后菜单收起。除了无横向溢出，还要检查菜单未遮挡表单和主按钮可操作。

## 账号与邮件组件补充

- 管理表格操作栏保持按钮同行：账号 300px、项目 400px、API 凭证 180px；窄屏取消固定操作栏，在表格内横向滚动，不遮盖账号信息、不压缩按钮或换行。
- 账号列表与详情展示 10 位账号 ID 和昵称；详情页只读展示昵称，仅用户本人可在账号与安全中修改。
- 邮件模板使用普通细边框或留白，不添加 `border-top: 4px solid #111111` 或其他粗顶部装饰线。

- “账号与安全”分别提供“通行密钥”和“iPhone 扫码登录”；扫码入口展示添加状态并使用独立添加页面，列表用标签标识已添加扫码用途的密钥。

- 超级管理员在账号列表昵称旁和个人资料标题处显示黑底白字的小角标，文字固定为“超级管理员”；普通账号不显示该角标。

- 项目 Logo 必须本地上传，编辑页提供预览与替换，不提供图床 URL 输入。列表与授权页按比例展示；旧项目未补传或加载失败时显示 project-default.svg，占位图不能用于通过必填校验。

## 页面容器统一规则

所有多鱼管理端与账号页面的根容器统一使用 `dy-page art-page-view`，包括列表、概览、新建、编辑、详情和安全设置。页面不再使用 `dy-editor` 的独立限宽；内部内容面板使用 `dy-panel`，跟随统一页面宽度。布局层继续负责路由容器与滚动，页面不另加窄版容器。

- 项目黑名单使用独立路由 `/manage/apps/blacklist`，根容器仍为 `dy-page art-page-view`；项目操作列宽 480px，手机在表格内滚动。开放准入仍受黑名单限制，避免显示“全部账号”造成歧义。

- 顶栏用户区域保留桌面 24px、手机 16px 右侧留白，长用户名截断并保留完整 title。页签菜单等图标使用构建脚本打包的 ri 本地图标，避免依赖未打包的在线图标集。

- 默认文字按钮统一为 32px 高、13px 中等字重、灰色文字，悬停与按下使用浅灰底，保留键盘焦点。返回入口使用 dy-back-button 浅灰底与 12px 底部间距；危险操作保留其语义颜色。

- 客户端类型通过 dy-client-options 整张卡片选择，不再显示重复的独立单选框；保留单选语义、方向键切换与焦点指示，已有项目禁用类型切换。

- 所有表格首列为跨页连续序号，每页固定 20 行；总数超过 20 才显示分页。分页置于对应 dy-panel 内的表格下方，展开的明细表也遵循此规则。

- 项目登录方式在项目配置中使用默认全选的复选组；个人账号页不提供这些开关。登录页隐藏关闭的入口，全部关闭时显示简短不可登录提示，不展示无效的操作按钮。

- 所有文本输入框与 textarea 统一使用 `font-size: 14px; border: 1px solid #ededee; color: #000000`。Element Plus 输入框由外层 wrapper 绘制单层边框，内部 input 不重复绘制；悬停和聚焦不加深边框、不添加光晕。单选框、复选框和文件上传控件保留原组件样式。

- 登录页接入项目 Logo 和名称位于 formside 内，与多鱼品牌一起位于左上角，按“项目 Logo＋名称 · 多鱼 Logo＋多鱼账号”同一行排列，字号统一为 20px，共用字重与图标尺寸；手机保持对齐，长项目名省略并保留完整 title。不使用 appbadge，不使用 .card h2:before 品牌前缀。

- 项目登录方式与应用平台使用带图标的整卡选择样式 dy-choice-options，沿用客户端类型的浅灰选中底和深色边框；隐藏原生复选方框和单选圆点，以卡片选中边框与底色展示状态；保留单选/复选语义和键盘操作，手机单列排列。

- 身份验证器使用独立账号安全页面，先验证邮箱，再显示绑定二维码与手动密钥，确认动态码后一次性展示恢复码；不把二维码、密钥、恢复码放入日志或持久化前端存储。登录入口使用“身份验证器登录”，注明支持 Microsoft Authenticator，不暗示微软账号或推送审批登录。

- 登录页其他方式使用横排固定卡片（84px 宽、80px 高、24px 图标在上、12px 文字在下），显示通行密钥、iPhone、身份验证器。隐藏的方式不占位，剩余卡片保持固定尺寸并居中；扫码返回按钮仍保持 42px。

- iPhone、iPad 与 Mac 的扫码页在二维码下面显示当前设备验证按钮；使用已绑定扫码用途的通行密钥，遵守 qr 登录策略，不受普通 passkey 开关替代。账号安全页对应三项统一使用 passkey.png、iphone.png、authenticator.png。

- 项目角色列表、新增/修改角色、用户角色分配使用独立页面。列表每页 20 行，首列序号，分页在 dy-panel 内；项目操作列 560px。项目登录选项中的三个图片图标与登录页一致。

- 管理端、登录页与扫码页统一 viewport：width=device-width, initial-scale=1.0, user-scalable=no, maximum-scale=1.0, minimum-scale=1.0。

- Apple 设备的“直接验证登录”入口不因缺少 PublicKeyCredential 而隐藏；HTTP 或浏览器不支持时保留禁用按钮并说明原因。仅跳转至服务器配置的 HTTPS origin；正常环境继续使用已绑定扫码用途的通行密钥。

- 账号管理列表与资料页展示已授权登录的关联项目及项目角色；未关联时明确显示“暂未关联项目”。账号头像加载失败使用默认头像。上传头像存储 /avatars/ 相对路径，避免端口、域名变更导致失效，OIDC picture 返回规范 origin 下的绝对地址。

- 账号管理列表的关联项目以 36px 可点击 Logo 排列，支持多个项目、悬停显示名称和角色；点击进入对应项目配置。缺失或加载失败使用 project-default.svg，保留链接的可访问名称。

- 项目管理 API 凭证使用独立列表/创建页面；接入文档和项目配置提供复制 AI 说明入口。普通复制不带密钥，新建凭证页的含凭证复制明确标识敏感内容；支持局域网 HTTP 的兼容复制。
