# 运维与恢复

本文说明当前运行期行为。首次安装和发布顺序见 [生产部署](deployment.md)，变量含义见 [配置参考](configuration.md)。

## 运行组件

- PostgreSQL 加密持久邮件队列，认证和项目邮件各有一个独立 worker，支持 `combined` / `api` / `worker` 运行角色。HTTP 提交项目邮件返回 `queued`，之后查询状态。
- 编号数据库迁移，事务 + advisory lock 防止并发执行；记录校验和，拒绝修改已应用迁移。Windows/Linux 换行统一后计算校验和。当前基线为 schema.sql，以后必须新增迁移，不修改基线。
- 可信代理白名单，不信任任意来源的 X-Forwarded-For。
- 数据库与本机 data 目录备份、隔离数据库恢复校验脚本。
- 未知邮箱/没有密码的账号同样执行 dummy Argon2id 校验，减少明显的计时差异；不承诺所有响应严格等时。

## 邮件运行

`DUOYU_ROLE` 默认 `combined`（API 与两个独立处理通道）。可拆成一个 `api` 实例与一个 `worker` 实例；两者必须使用相同数据库、DUOYU_SECRET 和 SMTP 配置。首次签名文件初始化仍由单实例完成；当前不是全面验证的多节点部署方案。

队列使用 AES-256-GCM 暂存正文，密钥从 DUOYU_SECRET 单独派生，任务 ID 作为附加认证数据。不得在存在待发任务时随意更换 DUOYU_SECRET。任务终态后清除密文，不保存正文历史。认证验证码沿用 challenges 的真实到期时间，发送前再次检查 challenge 是否仍有效；项目 verification 默认队列有效期 5 分钟，其他项目邮件 24 小时。项目自己的验证码实际有效期应与此相容，应用仍负责验证。

只有 SMTP DATA 正文提交前的明确临时错误/网络错误才重试，最多尝试 3 次，间隔 30、60 秒。超过有效期不重试。正文提交后的异常保守标为 unknown，不自动重发。进程异常终止导致 sending 超过 2 分钟时转为 unknown 并清除正文。queued/retry 状态在重启后继续处理。发送前再次检查项目、凭证和发信权限，撤销后的待发邮件取消。

两个通道各自每秒领取任务；SMTP 账号和进程资源仍共享，不能承诺所有大批量负载下完全隔离。恢复数据库备份后不要直接启动 worker，先审查 queued/retry/sending 任务：备份之后原系统可能已发送。严禁盲目重放恢复副本中的队列。

## 数据库升级

Windows 开发环境：

```powershell
./scripts/backup.ps1
./scripts/start.ps1 -MigrateOnly -Go '你的go.exe路径'
```

迁移模式只更新数据库，不启动 HTTP、worker 或初始化新签名文件。普通启动也会按版本应用待执行迁移。生产发布时建议先停流量、执行备份与迁移再启动；迁移脚本失败整笔事务回滚，不提供自动降级脚本。迁移后回退旧程序需先确认数据结构兼容；否则从经过验证的备份恢复。

## 可信代理

设置 `DUOYU_TRUSTED_PROXIES=127.0.0.1/32,::1/128` 仅在这些地址确实属于你的代理时使用。容器部署应填写实际代理网段，不要照抄回环地址。默认空值，不信任任何转发头；禁止 /0 白名单。

只有直连节点在白名单内才解析 X-Forwarded-For，从右到左跳过可信代理，遇到第一个非可信 IP 作为客户端。非法头回退直连 IP，防止伪造前缀绕过限流。入口代理应覆盖/正确追加该头，并限制客户端绕过代理直连服务。

## 备份和恢复演练

`scripts/backup.ps1` 默认适用于本机原生服务 + duoyu-postgres-dev 容器。创建全新的 backups/时间目录，包含 PostgreSQL custom-format dump、data 目录以及 SHA-256 清单。备份含签名私钥，目录权限应只允许管理员访问，并复制到受保护的异地存储。DUOYU_SECRET、SMTP 凭证单独安全保管，不写入清单。停止应用写入后备份可保证数据库和头像文件时间点一致。

```powershell
./scripts/restore-check.ps1 -Backup ./backups/你的备份目录
```

恢复脚本只允许创建新的 `duoyu_restore_*` 数据库，已存在目标会失败；不覆盖、不删除当前数据库。先验证文件哈希再以单事务恢复，保留恢复副本供检查。data 文件保留在备份中，不自动覆盖运行中的 data。切换生产数据库和数据目录应在停机窗口人工完成，并使用原 DUOYU_SECRET。

Docker 生产部署的 app-data 卷需要使用卷备份方式或提供该卷的只读快照路径；当前脚本不能自动备份其他主机的卷。未假设 Docker Hub 网络、生产 HTTPS 或真实设备已验收。

历史恢复演练及数据库副本见 [实现与测试报告](roadmap-implementation-and-tests-2026-10-27.md)。演练副本不启动 worker；备份不纳入 Git。生产恢复目标必须按实际数据规模重新演练。

## 管理与监控升级

当前已支持受限管理角色、服务端分页、审计清理、签名公钥保留、刷新令牌及后台退出通知。完整实现与本轮验收见 [建议落地与测试报告](roadmap-implementation-and-tests-2026-10-27.md)。

worker/combined 每分钟执行监控，告警/恢复去重写入审计。数据库容量默认阈值 10 GiB，可通过 DUOYU_DATABASE_ALERT_BYTES 修改；这里衡量数据库大小，不是磁盘剩余量。未配置外部告警通道。运行状态显示监控最后更新时间，超过 3 分钟提示检查 worker。

退出通知错误类别 invalid_endpoint、signing、transport、timeout、http_status 只保留脱敏分类，不保存响应正文或 logout token。人工补发只接受 failed，重置本轮次数但保留所有历史与原 jti。项目应在成功应用退出后记录幂等事件，重复通知返回成功。

API 凭证可在原记录上轮换，旧摘要保留至过渡截止，0 小时代表立即切换，最长 168 小时。已有过渡窗口不能再次轮换。丢失新凭证时可立即撤销此记录并新建凭证，不可恢复明文。修改权限或撤销作用于新旧凭证。

Windows 定时备份安装入口为 scripts/install-backup-task.ps1，必须显式指定绝对 DestinationRoot。脚本拒绝覆盖已有任务，不保存账号密码；默认每日 03:00，要求用户已登录且 Docker 可用。应用启动不会自动安装计划任务。生产无人值守需服务身份、适合部署环境的调度及离机保管方案。

生产 HTTPS、真实设备、真实邮件送达及故障恢复目标仍需在部署环境验收。

## 数据清理与容量

监控每分钟检查：退出积压超过 5 分钟、邮件积压超过 2 分钟、退出失败、邮件结果不确定、5 分钟登录失败达到 20 次，以及数据库容量达到配置阈值。状态变化产生 monitor.alert 或 monitor.recovered 审计事件，重复检查不会反复刷同一事件。登录失败指标是次数，不是按请求量归一化的错误率。

worker/combined 每 10 分钟分批清理，每类最多 500 条：过期中心会话、授权请求、WebAuthn 挑战、过期一天的验证码和限流记录，以及符合条件的旧令牌。已送达退出任务保留约 30 天，审计记录保留约 90 天；批量上限使实际删除可能晚于保留期。

当前不会自动清理全部旧头像、邮件幂等元数据和失败退出任务。制定清理方案时保留必要审计证据；删除幂等记录会失去对应键的去重能力。监控的数据库字节数不包含头像文件，也不能代替磁盘剩余容量告警。

## 三种密钥轮换

| 对象 | 操作与影响 |
| --- | --- |
| OIDC 客户端密钥 | 项目编辑页轮换后旧值立即失效，需要同步更新项目后端 |
| 项目 API 凭证 | 凭证编辑页支持 0–168 小时过渡，权限和原有效期不变 |
| 中心 RSA 签名密钥 | cmd/rotate-key 工具生成新私钥，保留旧公钥用于 JWKS 验签 |

签名工具适用于能访问真实数据目录的原生环境。先备份并停止所有 API/worker，再针对该目录运行：

```powershell
go run ./cmd/rotate-key -data ./data
```

完成后重启所有实例，检查 Discovery/JWKS 与新令牌验签。旧公钥至少保留到旧令牌与退出重试窗口结束，不要清空 verification-keys。Docker 数据在 app-data 卷，不是宿主机 ./data；运行镜像未包含 Go 工具链，需安排受控维护工具访问正确卷。

DUOYU_SECRET 不属于这三种常规轮换。它涉及摘要与队列解密，不能用随机替换该值代替签名密钥轮换。

## 故障定位

| 故障 | 检查与处理 |
| --- | --- |
| 认证 API 返回 503 | 检查数据库连通性；不要误当密码错误反复修改账号 |
| 队列持续积压 | 检查运行角色、worker 更新时间、数据库与 SMTP；不要只启动 api |
| 邮件 unknown | 核对实际收件与发送记录，避免盲目重发；恢复库尤其需要审查 |
| 退出通知失败 | 展开历史，区分 endpoint、签名、网络、超时与 HTTP 状态；修复接收端后由管理员补发 |
| 监控超过 3 分钟未更新 | 检查后台进程与数据库；全站故障需外部探活发现 |
| 凭证来源变化 | 结合最近 IP 和审计判断部署切换、NAT 或异常使用，不直接断言攻击 |

前端错误附带请求编号，安全日志可按编号查询；服务端事件日志记录相同 request_id。后台任务没有浏览器请求编号时，可按事件 ID、任务 ID 和时间追踪。日志不应包含密码、验证码、令牌与邮件正文。


## 项目黑名单

项目管理 → 黑名单，或项目编辑页 → 黑名单。所有项目默认空名单，填写账号 ID 或邮箱，每行一个；保存替换当前名单，清空保存即移除全部限制。最多 500 条，重复项自动合并；账号 ID 必须已存在，邮箱可以尚未注册。

黑名单优先于准入名单，仅作用于当前项目。从该项目授权登录页发送登录验证码、登录或自动注册会被拒绝；已有账号通过 SSO、通行密钥、手机扫码进入项目时也会在授权阶段被拒绝。账号中心和其他项目仍可正常使用，因此这不是全局禁止注册。

加入后撤销该项目已签发的访问令牌、刷新令牌和未兑换授权码，并排队发送已配置的后通道退出事件。移出黑名单不会恢复旧令牌，需要重新登录。项目自己的本地会话与已离线验证的 ID Token 无法被账号中心直接删除；接入项目应处理后通道退出，或在敏感操作时在线检查身份权限。

邮箱条目会关联已注册账号，未注册邮箱在之后注册时自动绑定账号；绑定后更换邮箱仍受限制。恢复访问请删除对应条目，并检查是否还有该账号的其他邮箱或 ID 条目。

管理接口：`GET /api/admin/apps/{id}/blacklist` 读取，`PUT /api/admin/apps/{id}/blacklist` 保存 `{"entries":["8888888888","blocked@example.com"]}`。仅超级管理员可管理，保存操作记录审计日志。数据库迁移 014 自动创建名单及令牌撤销触发器。


## 项目登录方式

项目编辑 → 允许的登录方式：邮箱验证码（code）、账号密码（password）、通行密钥（passkey）、iPhone 扫码（qr）、身份验证器（totp），新项目默认全选；017 迁移仅为此前四种方式全开的项目增加 totp，受限或暂停项目保留原选择。支持清空，清空后暂停该项目登录。项目保存接口 login_methods 为字符串数组；未传字段时新建使用默认全部，更新保留原策略，传空数组才表示全部关闭。

限制同时作用于登录入口、带授权请求的认证接口、SSO/静默授权、授权码兑换和刷新令牌；基于被关闭方式的现有 Access Token 在线检查也会被拒绝。需使用项目允许的方式重新验证。QR 与普通通行密钥分别配置，QR 的手机验证仍使用已绑定的通行密钥。

个人账号与安全页不提供项目开关。用户仍可管理全局密码、邮箱和通行密钥；中心登录与其他项目的配置不受本项目影响。移除请求上下文可登录中心，但无法使用该方式完成受限制项目的授权。项目策略以数据库当前值为准，已经打开的页面若未刷新仍会被后端拒绝。


## 账号关联项目与头像

账号管理和账号资料中的“关联项目”来自成功授权后的 app_users，显示项目名称和对应项目角色；中心账号可以关联多个项目。未完成项目授权的账号显示“暂未关联项目”，不将其误标为某个项目独有账号。列表可搜索项目名称。

管理员只能查看昵称，PATCH /api/admin/users/{id} 提交 name 会返回 403；用户通过 PATCH /api/me 修改本人昵称。

019 迁移把既有受管头像的完整 HTTP(S) 地址转换为 /avatars/{文件名}，保留本地图片文件。新上传也保存相对路径，管理端、个人页和局域网访问使用当前服务地址读取；OIDC profile.picture 使用当前 DUOYU_ORIGIN 拼成绝对 URL。部署需持久保存头像目录，不能只备份数据库。
