## 已实现

| 方向 | 当前行为 | 使用位置 |
| --- | --- | --- |
| 退出通知排障 | 保存 HTTP 状态、脱敏错误类别、耗时和逐次历史；数据库错误不再被当作空队列 | 运行状态，展开事件行 |
| 失败补发 | 仅系统管理员可补发 failed 事件；状态原子切换防止重复点击；保留原事件 ID 和 jti、目标项目与会话；每轮最多 10 次，历史不清空 | 运行状态，重新投递 |
| 管理角色 | 系统管理员、项目维护员、审计员、普通账号；后端逐接口允许清单，新增接口默认不授权给受限角色 | 账号管理 → 账号资料 → 管理权限独立页面 |
| 项目隔离 | 维护员只能列出负责项目，配置、准入、登录用户和客户端密钥操作均检查项目归属；不能管理全站账号、系统设置或 API 凭证 | 项目管理 |
| 审计只读 | 仅运行状态、退出通知记录和安全日志；无法修改任何管理配置 | 安全与设置 |
| 主动监控 | worker/combined 每分钟检查；告警和恢复状态持久化，重复轮询不重复写审计；监控失联提示 | 运行状态、安全日志 |
| 阈值 | 退出积压 5 分钟、邮件积压 2 分钟、退出失败、邮件结果不确定、5 分钟登录失败达到 20 次、数据库容量默认 10 GiB | 数据库阈值可设 DUOYU_DATABASE_ALERT_BYTES |
| 运维指标 | 最老任务年龄、数据库字节数、24 小时退出投递 P95；无样本显示横线 | 运行状态 |
| 接入自检 | 校验平台、回调、强制 S256 PKCE、退出通知地址和环境；接口返回最近失败退出事件编号；不主动请求任意回调 URL | 项目编辑 → 检查接入配置 |
| API 凭证轮换 | 0–168 小时新旧凭证并存；保留原权限与到期日；过渡期内拒绝再次轮换；撤销使两者失效；新值仅返回一次 | API 凭证编辑页 |
| 来源与追踪 | 记录 API 凭证最近 IP；来源变化写审计，不直接断言恶意；服务器生成请求 ID，贯通响应、审计与脱敏服务端事件日志 | 凭证编辑、安全日志、响应 X-Request-ID |
| 数据库故障 | 已登录请求遇到数据库不可用返回 503，不误报未登录，不开放权限 | 受保护 API |
| 列表交互 | 账号/项目/凭证/审计及邮件搜索 300ms 防抖、AbortController 取消、代次检查、卸载清理 | 管理列表 |
| 图标与主题 | 68 个静态引用图标本地生成并用离线组件；关闭未完整支持的暗色和布局设置入口，统一浅色 | 管理端 |
| 样式维护 | 登录、扫码 CSS 提取到 admin/public/auth；共用 42px 高度与基础变量；保留用户品牌资产 | 登录和扫码页 |
| 手机菜单 | 首次加载按屏宽折叠，手机导航后收起，折叠菜单不再遮住表单 | 管理端手机视口 |
| 测试与部署准备 | 新增 CI 协议、构建及代表性浏览器任务；新增明确安装的 Windows 每日备份任务脚本 | .github/workflows/test.yml、scripts/install-backup-task.ps1 |

角色分配不能授予或撤销系统管理员，系统管理员账号继续受保护。项目维护员能更改自己负责项目的回调与客户端密钥，应只授予可信的项目负责人；这不是业务系统内部角色。维护权限变更在下一个 API 请求立即生效，菜单刷新后更新。

监控告警目前进入数据库、运行页和审计；尚未接入外部短信、邮件或 webhook 告警通道。整个服务或数据库停止时，进程内监控不能替代外部存活探测。数据库指标是数据库大小，不是磁盘剩余容量。登录失败监控使用次数阈值，尚不是按流量归一化的错误率。

## 资源与迁移

新增不可变迁移 007_operations、008_monitoring，当前开发库已升级至 8 个版本。上线前先备份数据库、data 和独立保管的环境密钥；所有 API/worker 使用相同代码与配置，先执行迁移再部署。

管理主 JS 块约 1184 kB，gzip 约 389 kB；Element Plus 独立块约 478 kB，gzip 约 156 kB。拆包改善缓存边界，不代表总下载体积降低，尚未达到经过量化验收的首屏性能目标。

本地升级前备份：backups/pre-operations-upgrade。已恢复数据库副本保留用于核对，不是新的在线服务。现有原库数据未被恢复覆盖。

## 仍需完成的部署验收

1. 配置并核验 https://id.duoyu.link 的 TLS、issuer、WebAuthn RP ID、代理和 Secure Cookie；当前没有执行远端部署。
2. 提供至少两个正式接入站点，运行真实跨站 SSO、重新认证、刷新、退出与停权场景。
3. 真实 iPhone/Safari 和电脑浏览器验证通行密钥注册、取消、二维码拒绝/过期/重复确认及账号恢复。
4. 人工触发真实邮件并核对收件箱、垃圾箱和延迟；区分排队、SMTP 接受和实际送达。
5. 指定外部告警通道、备份保管位置和运行身份后启用部署配置。Windows 备份任务默认要求当前用户已登录且 Docker 可用；不能当作服务器无人值守方案。
6. 确定备份目标，例如每日快照对应最多约 24 小时恢复点；恢复时间目标须按实际生产库和文件量演练，不能沿用小型开发库耗时。

## 后续有条件的优化

- 深分页游标、字段搜索索引和大规模查询性能尚未重写。应先用代表性数据建立延迟目标与执行计划，再调整 API 与界面分页方式。
- 新增 Node.js/PHP 接入示例待明确实际业务语言；现有 Go 与浏览器 SPA 已完整联调，原生回调由协议测试覆盖。
- 完整读屏、200% 缩放、Firefox/WebKit、多浏览器真实跨设备、持续压测和独立渗透测试尚未完成。
- 第三方送达回执、外部心跳监控、认证错误率趋势及按实例监控仍需扩展；当前不宣称邮件送达或全系统健康。
- 客户端密钥仍是立即轮换；平滑过渡本次针对项目 API 凭证。受限角色尚不拥有 API 凭证管理权限。
