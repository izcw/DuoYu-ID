# 多鱼账号：界面更新、接入测试与完整优化方案

日期：2026-10-27。本轮基于本地项目实际代码、构建、协议测试、浏览器操作及截图检查。本文是当前功能与下一阶段工作的汇总，不代表已经完成公网部署或独立安全审计。

## 一、当前结论

多鱼账号已经具备统一身份认证、账号安全、项目准入、服务端凭证、公共项目邮件和基础运维能力。适合先接入自有 Web 项目；各项目继续保存自己的业务数据库，账号中心用 issuer + sub 提供稳定身份，client_id 区分项目。

本轮更新覆盖所有实际在用的多鱼管理/账号页面，以及登录、密码找回、已有会话确认和手机扫码确认界面。后台保留 Art Design Pro 布局，采用白/浅灰背景、黑色主按钮、细边框和小圆角，没有新增营销标语、业务数据库托管或文件托管。

最有价值的后续工作是完成生产验收、完善故障处理与审计，再按规模扩展管理权限。继续堆叠登录方式的收益低于把当前登录、退出、发信和恢复流程做可靠。

## 三、当前功能清单

### 认证与登录

- 邮箱验证码登录，验证新邮箱后自动注册，无额外注册勾选；后台可关闭新注册。
- 邮箱/密码登录，密码模式不要求邮箱验证码；邮箱验证后重置密码。
- WebAuthn 通行密钥注册、登录与移除。
- 手机扫码：桌面生成二维码，手机完成通行密钥验证和明确确认，桌面继续原项目回调。此能力不是 Apple 第三方账号登录。
- 已有中心会话复用，多标签页独立授权，prompt=login / max_age=0 重新认证，条件满足时支持 prompt=none。
- OIDC Authorization Code + S256 PKCE；发现文档、JWKS、签名 ID Token、UserInfo 与标准客户端认证。
- 按项目启用轮换 refresh_token；仅存摘要、限制 scope、并发消费保护、重放检测和家族撤销；绝对寿命不超过中心会话。

### 账号与项目

- 资料、头像、登录邮箱、密码、通行密钥和中心会话管理；逐设备撤销。
- 项目创建、修改、停用、客户端密钥轮换、回调及退出地址配置。
- 区分机密/公共客户端，以及 web/spa/native 平台。
- 项目准入名单、项目登录用户记录；项目停用和准入撤销影响授权与令牌。
- 全局用户身份不等于业务权限：业务角色、订阅、订单和内容仍由接入项目管理。
- API 凭证支持永久或指定有效期、权限范围、撤销和最近使用时间；凭证不代替用户登录令牌。

### 会话与退出

- 新访问令牌绑定中心会话，删除会话会撤销关联令牌。
- 可配置签名后台退出通知，持久队列、失败退避重试和状态记录。
- Go 示例验证退出事件签名、受众、时间、sid/sub 与事件类型，并处理重复事件。
- 项目可在线调用 UserInfo 验证当前状态；已签发 JWT 的离线验证不能代替停权检查。

### 邮件与运维

- 项目发送文字通知/业务验证码/告警时使用默认模板，也可提交自定义 HTML；后台不编辑或渲染项目 HTML。
- 项目级邮件权限、幂等键、状态查询、加密持久队列、认证/项目分队列处理、有限安全重试、终态正文清理。
- 编号数据库迁移和校验、备份及隔离恢复脚本、可信代理、基础限流、签名密钥轮换、公钥保留与定期过期记录清理。
- 管理列表服务端分页、基础审计、真实统计图表、管理员运行诊断。

### 未覆盖与限制

- 本轮没有发送真实邮件，没有切换 SMTP；邮箱验证码使用隔离测试数据，不构成 QQ 邮箱投递验收。
- 手机扫码使用虚拟认证器及独立浏览器上下文，不代表真实 iPhone、Safari、Face ID 或 iCloud 同步验收。
- 三个真实接入进程使用 localhost 不同端口，是不同 origin、相同 site；不代表不同正式域名下的跨站行为。
- 本轮没有生产压力测试、全部浏览器矩阵、全部 OAuth/OIDC 一致性认证或独立渗透审计。
- 正式域名 id.duoyu.link 上轮检查曾出现证书名称不匹配；本轮未重新验证公网 TLS。上线前必须复查，不能以本地测试代替。

不要优先添加短信、社交账号、业务数据托管或项目内密码直连。先由真实接入需求确认必要性，避免增加运营成本和认证边界。

## 六、建议修改

1. **明确两种退出。** 项目内退出只结束该项目；退出中心触发绑定令牌撤销和配置过的通知。按钮说明、接口文档和项目验收保持一致，不承诺任意第三方站点瞬时退出。
2. **统一客户端概念。** 管理端已区分平台与密钥能力，所有旧说明、外部示例和接入文档应继续按同一术语维护；公共客户端不是公开用户权限。
3. **扫码命名保持准确。** “iPhone 扫码”是自有二维码 + 通行密钥确认，不应宣传成 Apple 第三方登录。跨设备系统通行密钥交互也不应与自有二维码混为一谈。
4. **控制帮助文案长度。** 登录页只保留操作和必要状态；接入细节放文档和管理页面。运行页面保留“已接收/不确定”等真实含义，不展示虚假的健康评分。
5. **考虑后台主题边界。** 本轮验收默认浅色风格；如继续提供主题切换，应单独完成暗色对比度与图表验收，避免局部固定白色样式与暗色主题混用。

## 七、建议完善

### 生产验收优先

固定 `https://id.duoyu.link` 的 issuer 与 WebAuthn RP ID，检查正确证书、代理与 Secure Cookie。提供两个接入项目的正式 HTTPS 地址，执行首次注册、跨项目 SSO、重新认证、续期、退出、停权、断网和过期场景。不同 RP ID 下的本地通行密钥不能直接当作正式域名密钥。

实机验证 iPhone Safari、电脑 Chrome/Firefox，覆盖注册/取消/拒绝/过期/重复扫码与恢复账号。邮件验收需人工核对收件箱/垃圾箱及延迟，并区分入队、SMTP 接受与实际收到。

### 故障恢复与审计

对独立 worker 停止、数据库短暂不可用、SMTP 超时、退出通知端点不可达分别演练。退出通知达到重试上限后应有可追踪的人工处理流程；通知与在线验证作为互补，避免单一机制失效后仍无限接受本地会话。

备份已有脚本和恢复演练基础，应补部署侧定时调度、离机保管、恢复点与恢复时间目标。密钥轮换需覆盖所有 API/worker 实例，保留旧公钥直到旧令牌与重试通知窗口结束。

目前响应有 X-Request-ID，但还不是完整端到端可观测体系。下一步将请求编号、项目标识和错误类别贯通后台审计与服务端日志，禁止记录密码、授权码、验证码、令牌、邮件正文或完整回调参数。

## 八、建议优化

| 方向 | 当前依据 | 下一步与衡量方式 |
| --- | --- | --- |

| 数据查询 | 已实现服务端分页，但通用 JSON 文本搜索和 OFFSET 更适合小规模 | 按用户/邮件/审计分别设计字段搜索与索引；深分页改游标；以代表性数据的执行计划和延迟验收 |
| 交互请求 | 部分列表输入每次变化都会触发查询 | 增加短防抖和请求取消，保留代次检查；快速切换筛选不出现旧结果覆盖新结果 |

| 样式维护 | 管理端共用 CSS，登录/扫码仍是 Go 模板内样式 | 提取认证页面共用变量与样式，保持本地资源和无 CDN；以截图回归约束控件尺寸和间距 |
| 无障碍 | 本轮增强焦点及部分标签，未做完整读屏审计 | 检查键盘顺序、错误关联、表单标签、颜色对比度、缩放和读屏语义 |
| 运维列表 | 待发数量可见，但没有端到端时延和实时告警 | 增加最老任务年龄、成功率与延迟分位数；零积压不能代替送达或公网连通验收 |

## 九、建议执行顺序

| 阶段 | 工作 | 验收门槛 |
| --- | --- | --- |
| 1. 正式接入验证 | 修复/验证正式证书，两个不同站点、真实手机和真实收件检查 | 有完整场景记录和可复现失败信息，不能只确认首页能打开 |
| 2. 运行闭环 | 退出失败排障与补发、主动告警、定时备份、恢复目标、日志编号贯通 | 断网/停 worker/拒收故障可观察、可恢复，不发生重复发送或错误退出 |
| 3. 管理能力 | 角色分权、项目自检、凭证平滑轮换 | 无跨项目越权，轮换无需瞬时停服，操作有审计 |
| 4. 规模与体验 | 资源拆分、离线图标、查询索引/游标、请求防抖、浏览器与无障碍回归 | 达成预先定义的性能目标，并保持当前简洁风格 |

现阶段继续保持 Go + PostgreSQL + Vue/Element Plus，不为了“平台化”引入微服务或多个中间件。只有实测容量或组织需求超过现有方案，再增加新的基础设施。
